Organization of .dat files

Imaging datasets are stored in binary files with the extension .dat. Each .dat file contains only a single channel. For example, in a recording where a fluorescence channel was acquired with red and green illuminations, each channel is stored separately in a dedicated .dat file. These files are created using one of the available Data Import functions. The binary files store only imaging data as 4-byte (32-bit) floating-point values (single precision).

The file contains no header or dimensions. umIT reconstructs it using AcqInfos.mat in the same Save Folder, and all .dat files in that folder share the recorded height and width.

Ordering

MATLAB array: data(Y, X, T)
Serialized order:
  frame 1: column X=1 from Y=1..Height, then X=2, ...
  frame 2: same Y-X order
  ...
  frame T

This is MATLAB column-major Y-X-T order. The byte offset for pixel column x in frame t follows the same order; each value uses four bytes.

Metadata and file naming

AcqInfos.mat provides Height, Width, Length/frame count, frame rate, channels, and multi-camera facts. File names identify logical channels or processing results, but names alone do not define dimensions.

How DataViewer reads data

DatImageSource validates file size against metadata, uses direct fseek/fread frame and pixel reads, and maintains an optional spatial-temporal cache. DataViewer does not require the whole recording in RAM. The lower-level mapDat helper is available for suitable programmatic workflows, but mapped size and type must still come from validated metadata.

Processing lifecycle

Analysis functions can return arrays for PipelineManager to persist, or accept a filename and stream spatial slabs for low-RAM processing. New outputs receive processing provenance in dataHistory.mat. Event-aligned additional dimensions are normally stored in UMT rather than changing the raw binary contract.

Programmatic access

info = loadMetaData("C:\save\green.dat");
data = loadData("C:\save\green.dat");      % use when it fits in memory
% For large files, use DatImageSource or spatialSlabIO.

Never edit bytes or metadata independently.
Do not change precision, reshape assumptions, file length, AcqInfos.mat, or one camera file without the controlled importer/analysis operation that owns the change.
