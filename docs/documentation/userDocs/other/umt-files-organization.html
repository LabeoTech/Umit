Organization of .umt files

Every .dat file in a Save Folder follows the dimensions in AcqInfos.mat. Processing results do not always fit that Y-X-T layout: an amplitude map has conditions instead of time, an ROI trace has an ROI axis, and a correlation matrix has two ROI axes. UMT files exist to store these smaller processed or reduced results together with their own named dimensions and scientific context.

A typical imaging pipeline uses .dat for the high-volume image time series and .umt for intermediate or final measurements. DataViewer can open compatible image-kind UMT entries.

Top-level structure (version 1)

FieldRequired?Meaning
versionYesUMT format version used during validation.
kindYesimage or roi; determines which combinations of dimensions are accepted.
dataYesStructure containing one or more named measurement entries.
labelsNoShared display/reference labels.
eventInfoFor event-axis dataShared condition names, identifiers, repetitions, and optional baseline duration.

Entries are measurements

Think of each data.<entryName> as one measure derived from a dataset. For example, a single UMT file could contain an ROI-by-time fluorescence trace, an ROI-by-measure response summary, and an ROI-by-ROI correlation matrix. These entries can have distinct dimensions because each entry declares its own:

Entry fieldMeaning
valueThe numeric or logical measurement.
dimNamesThe ordered meaning of every dimension, using names such as Y, X, T, E, F, ROI, Pixel, or Measure.
metaOptional processing information specific to that measurement, including FrameRateHz where applicable.

The number and order of dimNames must match value. Every entry must also match a supported pattern for its UMT kind.

Event information

FieldMeaning
eventIDCondition ID for each E-axis element.
repetitionIndexRepetition number, or zero for a result already aggregated across repetitions.
eventNameCondition name corresponding to each E-axis element.
eventAxisModeinstances or aggregated_repetitions.
baselinePeriodOptional baseline duration in seconds.

Create, append, and validate

Normally an analysis function constructs a UMT result and PipelineManager passes it to the next step or saves it when required. For advanced MATLAB use, create and append entries with genUMTStruct:

% Create an image time-series measurement.
umt = genUMTStruct(imageData, ...
    'kind', 'image', ...
    'entryName', 'correctedFluorescence', ...
    'dimNames', {'Y','X','T'}, ...
    'SaveFolder', saveFolder);

% Append a Y-X amplitude measurement to the same container.
umt = genUMTStruct(umt, ...
    'value', amplitudeMap, ...
    'entryName', 'peakAmplitude', ...
    'dimNames', {'Y','X'});

validateUMTStruct(umt, 'requireEventInfo', false);
save(fullfile(saveFolder, 'processedResults.umt'), '-struct', ...
    'umt', '-mat');

Use appendUMTEventInfo when one or more entries declare an E dimension. Validation requires all E-based entries to use the same E length and the event vectors to match it.

Project identity stays outside the UMT file
A UMT file can carry scientific labels, dimensions, events, and processing information. Project, subject, and session organization remains in the central project information and the Save Folder link; folder-wide masks and Raw Folder paths remain in DataParams.mat.

Previous data and manual editing

Processed data created with the previous release, especially results saved as general .mat files, may not be compatible with the UMT structure. Load and convert those results deliberately; changing the extension does not convert the data.

Validate every UMT loaded or changed in MATLAB. Direct field editing is unsupported because a small change can make entry dimensions, labels, or event information disagree.
