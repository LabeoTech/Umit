Events

An event marks a stimulus, behavioral condition, or other interval that can be aligned with imaging frames. Continuous .dat recordings use events.mat in the Save Folder; event-split UMT data carries its own top-level eventInfo.

The EventsManager class creates, validates, loads, and saves events.mat. The Events Manager app is its graphical interface and provides convenient controls for event detection from LabeoTech imaging-system analog inputs.

Current events.mat variables

In the table, N is the number of analog samples, K is the number of recorded or selected analog channels, M is the number of detected ON/OFF transitions, and C is the number of conditions. Empty values are permitted where the corresponding source or option is not used.

Detection, conditions, and repetitions

  1. EventsManager uses the threshold, polarity, trigger type, minimum inter-stimulus interval, and optional filtering to identify event transitions.
  2. An optional condition file assigns condition IDs and names in chronological order. Without one, supported digital or generic detection rules assign the conditions.
  3. Repeated event IDs become repetitions of the same condition.
  4. The baseline duration and acquisition frame rate determine which imaging frames precede and follow each event.

Detect an external signal in MATLAB

The current app does not expose this workflow, but the class can detect one numeric trigger signal that was acquired outside a LabeoTech system:

saveFolder = "C:\data\mouse01\session01";
signal = readmatrix("external-trigger.csv");
sampleRateHz = 1000;

ev = EventsManager(saveFolder);
ev.trigType = 'EdgeSet';
ev.trigPolarity = 'positive';
ev.trigThr = 'auto';
ev.getTriggersFromSignal(signal(:,1), sampleRateHz, true, ...
    'FilterFreq', 0);
ev.saveEvents();

getTriggersFromSignal treats the vector as one condition named extSignal, updates the object, and records b_hasExternalSignal=true. Inspect the detected events before calling saveEvents.

Validation and ignored trials

The class checks field types and compatible lengths, validates timing against acquisition information when available, and prevents unusable frame selections. A missing file disables event features; malformed event information is not guessed from imaging intensity.

When a condition or repetition is deleted in DataViewer, its entries in selectedEvents are set to false and saved in events.mat. The signal and timestamps are not erased. The ignored trials remain excluded from later DataViewer displays and from analysis functions that use events.mat, until they are restored.

Event information in UMT files

When continuous data is split into trials, the UMT file keeps the event-axis description at top level so it remains interpretable outside the original Save Folder. For an entry with an E dimension, each E element must match one row of the event vectors.

Replace an existing events.mat only through the tool or validated code, and keep backups for irreplaceable event annotations.
