Save Folder metadata files

A Save Folder keeps recording data and recording-local state together. Centralized project identity and managed resources remain outside it.

File/patternAuthoritative purposeOwner and editing rule
AcqInfos.matImported dimensions, frame rate, channels, exposure, multi-camera facts, and information required to reconstruct .dat.Import or controlled migration code. Required for .dat; never invent or hand-edit replacements.
DataParams.matSave Folder analysis/view state: coordinate convention, pixel scale/origin, logical mask, registration state, and folders.RawFolder.DataViewer and DataParams helpers. Missing/invalid state falls back safely; update through the app or validation helpers.
events.matContinuous recording event timeline, conditions, repetitions, baseline, and detection source.Events Manager. Optional for ordinary viewing.
dataHistory.matPer-output processing provenance: steps and options that produced files.PipelineManager execution. It is not the live graph or project database.
pipeLog.matPer-step execution log for the folder.PipelineManager execution; inspect through Pipeline Manager or MATLAB.
*.roiSchema-validated ROI definitions, geometry, names, colors, and image-size context.DataViewer ROI tools and ROI helpers. Do not insert graphics handles or edit fields casually.
*.datContinuous single-precision image samples.Import and analysis functions. Read with approved APIs; registration apply may rewrite all files.
*.umtSelf-describing processed or derived data with dimensions and event information.UMT constructors/validators and PipelineManager persistence.
PMTMP_*DataViewer-managed temporary pipeline outputs.PipelineManager/DataViewer lifecycle. Save a permanent copy before switching or closing.
UMITProjectBinding.umitlinkProject, subject, session UUID locator plus hints for this processed-data folder.Project Binding Manager. Never a second metadata database and never silently rebound.

Ownership flow

Importer ---- owns ----> AcqInfos.mat
DataViewer ------------> DataParams.mat and .roi
Events Manager --------> events.mat
PipelineManager -------> outputs, dataHistory.mat, pipeLog.mat
Project Binding -------> UMITProjectBinding.umitlink
Central stores --------> project identity and managed resources

Centralized versus local

The centralized store is authoritative for project, subject, session, rig identity and managed image references/transforms. The Save Folder is authoritative for recording samples and local application state. When a central transform is applied, DataParams.mat stores the applied resource UUID and local outcome; it does not duplicate the resource registry.

Do not use DataParams as backup acquisition metadata.
Even if it contains image-related view fields, it cannot substitute for missing AcqInfos.mat when reading .dat.
