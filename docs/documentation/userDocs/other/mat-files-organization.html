Save Folder metadata files

A Save Folder keeps imaging data and recording-specific information together. Project information and managed image references or transforms are held in the user's central umIT folder, but UMITProjectBinding.umitlink links the Save Folder to its project, subject, and session.

All .dat files in one Save Folder share the same image height and width. Those dimensions, together with the information needed to read the binary data, are stored in AcqInfos.mat. Files whose dimensions differ use the .umt format.

Do not remove AcqInfos.mat
Without AcqInfos.mat, the toolbox cannot reliably reconstruct the images in the Save Folder's .dat files. Removing it renders those files unreadable to umIT.

Use the interface that owns each file
These files are coordinated with other application state. Do not hand-edit them unless you understand the validation and update rules; use the app, class, or helper listed above.

AcqInfos.mat

The file contains one scalar structure named AcqInfoStream. Import functions create it from the source recording. Its exact optional fields depend on the importer and hardware, but current readers use these groups:

FieldsMeaning
Height, Width, LengthShared Y-X image size and imported time length. Readers also verify the actual file size before trusting a frame count.
FrameRateHz, ExposureMsecImaging time base and acquisition exposure.
DatatypeBinary sample type when supplied. Current imported .dat imaging files use 32-bit single precision.
ImportedChannelsPer-file channel records used to match a .dat filename to its channel and timeline.
MultiCam and camera/channel fieldsDual-camera acquisition layout, rotations, flips, binning, and channel associations when present.
Hardware/importer-specific fieldsAdditional facts preserved by the importer, such as analog channel names or source acquisition information.

DataParams.mat

The file contains one scalar DataParams structure. It is created and validated independently from acquisition metadata; it cannot replace AcqInfos.mat.

GroupContents
Top levelschemaVersion, creation/modification times, and optional notes.
viewimageSizeYX, image-axis convention, pixel scale, and the image origin used for calibrated coordinates.
maskThe folder-wide logical mask plus its name, description, coordinate space, source, and creation time.
foldersThe Raw Folder path, its availability status, and when/by whom it was set.
registrationSingle-camera alignment status, reference information, transform, review/application history, QC files, and QC measurements.
cameraCoregistrationDual-camera transform status, rig/resource references, review/application history, QC files, and QC measurements.
customReserved validated space for additional recording-level information.

events.mat

This MAT-file stores separate variables rather than one enclosing structure. They include the analog input matrix, sampling rate, trigger threshold/polarity, timestamps and ON/OFF states, condition IDs and names, baseline duration, condition-file settings, and selectedEvents flags. See Events for the full field, class, and dimension table.

dataHistory.mat

The file contains a structure array named dataHistory, with one current entry per saved output filename:

FieldMeaning
fileOutput filename within the Save Folder.
timestampWhen this history entry was produced.
pipelineVersionVersion of PipelineManager that assembled the record.
infoOrdered processing steps. Each step records its function name/version, parameter values, and named input sources. Existing history from a saved input is carried forward where applicable.

pipeLog.mat

The file contains a table named pipeLog. Each row describes one attempted step. Columns include NodeTag, FunctionName, NodeID, Status, start/end times, duration, input source, output files, and short/full messages. It is an execution log, while dataHistory.mat describes the provenance of files that remain in the folder.

UMITProjectBinding.umitlink

This link file contains one ProjectBinding structure with a format version, binding identifier, project/subject/session identifiers, the folder role (rawDataFolder or processedDataFolder), and creation/modification times. It is a locator, not a copy of the project information. Use Project Binding Manager to bind, rebind, repair, or remove it.

Local and centralized information

Save Folder                           Central umIT project folder
-----------                           ---------------------------
imaging files and local metadata <--- .umitlink ---> project / subject / session
                                                   image references and transforms

The Save Folder remains a self-contained location for one recording and its processing history. The central project folder provides organization across many recordings and keeps resources that should be shared between sessions. The link connects the two without requiring a particular name or folder-tree layout for the imaging data.
