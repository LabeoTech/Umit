Folder rig

This page is for users of rig-dependent processing, for example hemoglobin computation with HemoCompute. Viewing data, ROIs and most processing do not depend on the rig.

Every Save Folder keeps its own record of the rig its data came from: the folder rig ledger (UMITRigLedger.json, see Save Folder metadata files). It is the single source of rig information for that folder. The rig library of your computer is used only to author rigs and to choose one; analysis functions such as HemoCompute read the optics from the folder ledger, never from the library. Opening data in DataViewer never writes to the folder.

Rig states in the context line


The rig part of the context line in the different folder states.

TextMeaning
unknown (no rig ledger)The folder has no rig ledger, for example data imported by an earlier release. Bind a rig before rig-dependent processing.
none (no rig)The folder was imported without a rig (single-camera data, TIFF import, or dual-camera data imported without coregistration). Bind a rig before rig-dependent processing.
the rig name, for example Rig AThe folder is bound to that rig, and no rig-dependent result has used it yet. The rig can be changed freely.
(committed) after the nameA rig-dependent step (for example HemoCompute, or a dual-camera import that applied a coregistration) used the rig's optics or coregistration. They are now committed to the folder: rebinding to a rig whose optics differ creates a conflict.
- CONFLICT after the nameThe folder was rebound to a rig whose optics differ from the committed ones. Rig-dependent processing is blocked until the conflict is resolved.
[had conflict]A permanent mark: the folder had a rig conflict at some point. The details are in the Rig Ledger History.
invalid rig ledgerThe ledger file is damaged or was edited by hand (see below).

Bind or rebind a rig

  1. Choose Management > Rig > Folder Rig > Bind / Rebind Rig....
  2. Pick a rig. The list holds the Active and Available rigs of the library; the Active rig is pre-selected. Archived rigs cannot be bound.
  3. Confirm. For a folder without a rig the confirmation only names the rig and the folder. When the folder already committed optics and the chosen rig's optics differ, a warning names both rigs and explains that the folder will become CONFLICTED; choose Rebind to continue or Cancel.

The warning shown before a rebind that changes committed optics.

Binding or rebinding changes the folder's optics only. The camera coregistration of a dual-camera folder stays as it was imported: it changes only through a re-import of the raw data (see ImagesClassification).

Resolve a rig conflict

A conflicted folder can be fixed in three ways:

  • Revert: rebind the folder to the rig whose optics were committed.
  • Start again: re-import the raw data into a fresh Save Folder.
  • Acknowledge: choose Acknowledge Rig Conflict... to accept the current rig for this folder. The dialog explains the conflict; you may enter a comment, which is stored in the ledger. Results computed before the rebind are not changed, but they are not reused either: when a pipeline is run again with step skipping on, rig-dependent steps that ran before the acknowledgement are recomputed. The folder keeps the permanent [had conflict] mark.


Acknowledging a conflict, with an optional comment.

Rig Ledger History

The history lists the folder, its state and bound rig, then one line per event: noRig (imported without a rig), bind, rebind (with what changed in the optics and the coregistration), commit (which part was committed, and by which step), conflict, acknowledgeConflict (with its comment) and freshImport (a re-import reset the commitments). Rigs are named as they were recorded, so the history reads the same on a computer whose library does not have them.


The history of a folder that was bound to Rig A, used by HemoCompute, rebound to Rig B and acknowledged.

Invalid rig ledger

If the ledger file is damaged or was edited by hand, DataViewer still loads the data and shows the alert Invalid Rig Ledger. Rig-dependent processing (for example HemoCompute) is then refused for the folder. There is no repair tool: restore UMITRigLedger.json from a backup, or re-import the raw data into a fresh Save Folder.
