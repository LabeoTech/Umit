normalizeBSLN - Normalize by baseline

Normalizes image time series or image time series split by events using a baseline time period.

Description

This function calculates the relative response change from the median value of the frames from a baseline time period at the beginning of the recording (for image time series) or trial (for image time series split by events). The baseline time period is set by the parameters normalizationMode and baselineMode.

Input

This function accepts a .dat file with axes Y,X,T (image time series) or Y,X,T,E (image time series split by events, e.g. the output of split_data_by_event), or a single-precision array with the same layout (3-D for Y,X,T and 4-D for Y,X,T,E). UMT structs and .umt files are not supported.

A .dat file is streamed in X slabs sized from the available RAM and the output is written slab by slab (Low-RAM mode is always on). An array is normalized in RAM; the peak memory is the input, the normalized copy, and a baseline-sized temporary. Both input types give identical values. Continuous data are not split by this function: to normalize by trial, split the data first with split_data_by_event.

Note
MATLAB drops a trailing singleton axis, so an event-split array with a single trial (E = 1) arrives as a 3-D (Y,X,T) array and cannot be used in trial mode. Use the .dat file in that case.

Warning
The result is divided by the baseline, so the input must be raw intensities. Data that are already zero-centered (the output of normalizeBSLN itself with b_centerAtOne set to false, the output of normalizeZScore, or a baseline-subtracted signal) have a baseline close to zero, and dividing by it gives results of arbitrary size.

When at least 20% of the pixels (and trials) have a baseline smaller than 3 times the spread of their baseline frames, the function raises the warning Umitoolbox:normalizeBSLN:ZeroCenteredInput, once per call, however many slabs the file is read in. The run continues and the result is not changed. The warning appears in the MATLAB Command Window and can be silenced with warning('off', 'Umitoolbox:normalizeBSLN:ZeroCenteredInput'). Data centered at one (b_centerAtOne set to true) are not flagged. The check needs at least 3 baseline frames and is skipped with fewer.

The algorithm

For each trial (or the whole recording, for image time series), the function calculates the response amplitude as the pixel values over time minus the baseline (ΔR). Then this result is divided by the baseline resulting in pixel values expressed as ΔR/R. Here, the baseline corresponds to the median value of the baseline frames, omitting NaN values; a zero baseline is replaced by 1. The baseline period is defined by the parameters normalizationMode and baselineMode.

Output

For a .dat input, the output is the normBSLN.dat file (saved in the save folder) with the same axes and sizes as the input, in single precision. A Y,X,T,E file keeps its E axis: every trial is normalized on its own, ignored event instances included, so the E axis still matches events.mat. For an array input, the output is the normalized single-precision array, with the same size as the input, and nothing is saved to the save folder.

Parameters

In recording mode, which is for Y,X,T data, the baseline is taken from the start of the recording.

In trial mode, which requires Y,X,T,E data, the baseline of every trial is the baseline (pre-event) period stored in events.mat, found in the save folder.

Recording mode does not apply to event-split (Y,X,T,E) data. If it is selected for such data, the function warns and uses trial mode instead (a numeric baselineMode is then ignored).

In recording mode (Y,X,T data), the auto setting uses the first frames encompassing 20% of T, while a number sets the baseline as the first baselineMode seconds.

In trial mode, this parameter must be auto: the baseline is the baseline period of events.mat.

Frame rate (in Hertz) of the data, needed to convert a numeric baselineMode and the trial-mode baseline into frames. When the function runs in a pipeline, the value is taken from the data flowing into the step; otherwise it is read from the .dat header. An array has no header, so when calling the function directly with an array, this parameter must be provided if baselineMode is a number or the mode is trial.

Set this parameter to true, to center the normalized data to one (data average ≈ 1). Otherwise, the data will be centered at zero (data average ≈ 0).

Tip
Centering the normalized data to one is useful if other calculations of value changes (Δ) will be performed later on the analysis. In those cases, centering the data at one will avoid any divisions by zero or values too close to zero.
